## 龙芯杯简介
龙芯杯比赛内容是设计CPU。使用vivado将设计代码综合到fpga后，根据CPU运行测试程序的时间进行排名。

## 报名参加
去年，大二下学期，实验室老师，体系结构课老师，还有一位学长A，都向我推荐过龙芯杯比赛。当时的我浑浑噩噩，得过且过，对学习提不起兴趣，也没有关于比赛的基础知识，只是草率报名。报名后，进展不多，没能做出像样的作品。比赛截止前夕，恰逢前往北京参加国科大的活动，如井底之蛙跃出井口，方知世界之大，又重燃起斗志。可惜所剩时间不多，准备下一年认真备赛。

大三上，课业繁重，想备赛却有心无力。寒假，开始学习“一生一芯”，并通过预学习。大三下，正式备赛龙芯杯。

## 初赛备赛
### 大三下
大三下，课业压力小。三、四月复习Verilog知识，跟着《CPU设计实战》学习单周期和部分五级流水线CPU的设计。五月，参照学长A的思路制作了指令模拟器，与之不同的是，我将emu封装为类，方便调用，为此还学习了一段时间的 C++ 。六月，基本完成五级流水线的学习。六月底回家，休息一阵。

### 七月
七月一日，正式开始。先学习了 System Verilog，然后开始写代码。因为理论扎实，五级流水线写得快。icache和bp也没有问题，一个星期完成。在对拍时，感觉传统波形图看得眼花，于是自制一个简易的波形图工具，方便debug。后面串口有问题，花了一些时间去改。
![波形图工具](73383bb2-ed14-4f3a-8b68-885709605c47)


我在ubuntu 24 里写代码，而vivado装在ubuntu 18，每次综合bitstream都要复制粘贴代码，比较麻烦。因此将vivado装入ubuntu 24，提高效率。但兼容性有问题，便寻找解决办法。 <a href=https://xingwangzhe.fun/posts/1a282b79/ >Ubuntu 24.04 安装 Vivado 2018.3</a> 总结一下，因为一个底层库更新了，vivado无法识别。解决方法是将需要的库连接到最新的库。
```bash

sudo ln -sf /lib/x86_64-linux-gnu/libtinfo.so.6 /lib/x86_64-linux-gnu/libtinfo.so.5
sudo ln -sf /lib/x86_64-linux-gnu/libncurses.so.6 /lib/x86_64-linux-gnu/libncurses.so.5
sudo ln -sf /lib/x86_64-linux-gnu/libncursesw.so.6 /lib/x86_64-linux-gnu/libncursesw.so.5
```

把bitstream提交到平台时，还要一个一个点击，于是做了一个脚本，把bit流自动上传到各个测试题目。

七月中旬，突然通知今年wns要求为正，这样就不能无限制超频，利好复杂架构。五级流水线设计通过测试后，尝试单发乱序，把ex阶段和mem阶段并行，速度提升明显。因为用的简单的乱序架构，所以一天就完成了，不过后续对乱序的验证花费不少时间。

七月下旬，发现一个棘手的问题，我的设计会随机地无法通过测试，相同的bitstream有时通过，有时不能。仿真无异常，说明是上板的问题。花费很长时间都找不到错误，无奈之下把网页版的远程fpga封装成cli，让AI大范围跑测试找问题，最终定位到一组特定的指令序列 —— 连续st就会出错，增大延迟也不行。解决方法是在连续st之间插入强制we=0。（特别注意，我把远程fpga封装成cli也是迫不得已，实在是bug太难找，请大家不要随意模仿）

七月中旬排行榜开启，竞争激烈。七月下旬，我的成绩已远远落在后面，深感无力。尝试加入write buffer，勉强提升10ms，通过仿真发现 ld 和 st 相隔较近，buffer的访存被流水线指令频繁打断，提升不如预期。w buffer提升的10ms仍是杯水车薪，差距依然明显，各榜单都进不了前20。

### 八月
八月五日，初赛截止，身心俱疲，预感决赛无望，没再优化代码，在家躺了几天。八月十二日，决赛名单公布，发现自己进入决赛，十分惊喜。然而决赛人数较往年的50名增加至80名，并新增“优胜奖”，不再保底“三等奖”。心想我大概是因为今年新增参赛名额才能进决赛，也许最后只能拿优胜奖，算是喜忧参半。

得知进决赛后，我开始新增指令，优化时序。重新检查代码时发现w buffer有问题，如果字节和字的访存交叉在一起，w buffer无法正确判断是否命中，访存会出错。为了稳定不出差错，并且时间也所剩不多不一定能改好，只能删掉w buffer。分支预测也有问题，二位饱和计数器只会向 11 移动，不会向 00 移动。但是分支预测不影响程序正确性，实验发现对于测试程序的ipc几乎没有影响，所以没再修改。优化时序是一件玄学的事情，修改一点sv代码，因为布线差异，时序就可能大不一样。抽卡抽到几个较好的时序，就没再修改。

决赛是写汇编程序，我担心写不好，便完成其余常见的指令，这样使用C语言写完编译即可。剩余未完成的指令，只要不写特定的C代码就不会被编译出来。我总结了三种例外情况，这三种的硬件实现会显著拖慢主频，所以可以用软件实现。
1. short类型 会出现 ld.h ld.hu st.h。
2. long long乘法会出现mulh.wu。
3. 除法、取模会生成div.w  div.wu  mod.w  mod.wu
学长A还推荐写自定义指令，我认为这不符合要求，且debug不方便，没有做。现场改cpu设计是允许的，但我cpu的设计是抽卡来的，改一点就要降频，现场综合时间又长，不太可能在四个小时内改完，所以没想着改。

19日提交最终代码，20号提交alpha测试。aplha测试是新增的内容，是测试程序的加强版，据说是用来筛选一些违规的设计。看群里有人的alpha测试有问题，庆幸我交的是比较稳定的版本，没有冒险把w buffer的版本交上去。

比赛题目相较于往年的求和、比大小这类难一些.

``` 比赛题目

1. 题目： 二值点积运算
给定 0x40000 组 32 位输⼊ (lhs, rhs) ，计算每组输入的二值点积。

2. 计算规则：
每组输入由两个 32 位数据 lhs 和 rhs 组成，视为 32 位二值向量。每 bit 表示一个二值元素：bit 值 0 表示数学值 -1 ，bit 值 1 表示数学值 +1 。
定义：
A[j] = lhs[j] == 1 ? +1 : -1
B[j] = rhs[j] == 1 ? +1 : -1
其中 j = 0, 1, ..., 31 。每组的点积结果定义为：
result = A[0] * B[0] + A[1] * B[1] + ... + A[31] * B[31]
result 作为 32 位有符号整数存放。


3. 输入与输出：
输入位于 BaseRAM 0x1c200000–0x1c3fffff ，每组占 8 字节并按小端序交错存放：
lhs[i] = *(uint32_t *)(0x1c200000 + 8 * i)
rhs[i] = *(uint32_t *)(0x1c200004 + 8 * i)
result[i] = *(int32_t *)(0x1c400000 + 4 * i)
每组结果依次写⼊ ExtRAM 0x1c400000–0x1c4fffff。 
```


``` C

#define MEM32(a) (*(volatile unsigned int *)(a))

int main(void)
{
    unsigned lhs_addr = 0x1c200000;
    unsigned rhs_addr = 0x1c200004;
    unsigned result_addr = 0x1c400000;
    for(unsigned int i=0;i<0x40000;i++){
        unsigned lhs_i = MEM32(lhs_addr + i*8);
        unsigned rhs_i = MEM32(rhs_addr + i*8);

        int result_i=0,a0=0;

        unsigned temp_i = lhs_i ^ rhs_i;

        for(unsigned j=1;j!=0;j = j<<1){
            unsigned ta = (temp_i) & j;
            a0 += (ta == 0);
        }
        MEM32(result_addr + i*4) = (a0+a0-32); 
    }
}

```

C语言写的没通过，检查几次后发现有个循环变量写错了，修改后正确了。

### 行程反思
1. 退房前要仔细检查物品是否带齐。龙芯杯的短袖和床被的颜色一样，都是一样的白色，没看清，落下了。后来联系前台我，当时早已上车，没时间返回，只能邮寄回来。

## 一些感想

### 侥幸拿到三等奖

赛前觉得拿不到奖的原因是我的成绩在四个测试的榜单都排不到前20，且与20名的差距不小。今年三等奖人数基本不变，我的排名在三等奖的靠后，估计一下大概在龙芯赛道的三十名左右，擦着线，仅看初赛成绩这也勉强说得通。在考虑到决赛，有可能是最后的汇编题目性能稍好，或者alpha测试筛掉了一些硬件加速器，或者决赛筛掉了一些不会写汇编代码的，总这这个成绩能拿三等奖也还算合理。


### 最终作品
最终提交的作品是单发射乱序处理器，icache+bp，ex阶段和mem阶段并行，使用记分牌避免waw冲突。性能上，ipc=0.5, 150MHz，ips约为75。随着AI发展，未来的竞争会更加激烈，建议下一年ips应当80往上，采用更加复杂的架构。今年起，决赛不再保底三等奖，又新增了一个“优胜奖”，所以进了决赛也不能大意。

### 备赛之艰
备赛一个多月，身心俱疲。之前我一般十点起床，自备赛以来，心中藏事，常常七八点就醒。遇到bug或是难写的模块，像是write buffer，访存bug，更是做梦都能梦到，做梦都在折磨我。晚上睡不好，醒来自然是头脑昏沉。有时候一些bug卡了一两天，心中不免惊慌：这个bug会卡住多久？万一比赛截止前还做不好岂不是直接0分全部白干？这样的焦虑我从未遇到过，即使理智告诉我不必惊慌，但心脏仍止不住地嘭嘭乱跳。这份惊慌焦虑，这样心中有事睡不好觉的情况，即使高考前几个月也没有出现过，实在是令人身心俱疲。

不过最终是咬牙坚持下来，这份毅力也是这次比赛给我的重要收获。

假期还有校园跑的补跑，每天晚上能出门放松一下，也能稍稍减缓心中的压力。
