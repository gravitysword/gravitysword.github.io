## 龙芯杯简介
龙芯杯比赛内容是设计CPU。使用vivado将设计代码综合到fpga后，根据CPU运行测试程序的时间进行排名。

## 报名参加
去年，大二下学期，实验室老师，体系结构课老师，还有一位学长A，都向我推荐过龙芯杯比赛。当时的我浑浑噩噩，得过且过，对学习提不起兴趣，也没有关于比赛的基础知识，只是草率报名。报名后，进展不多，没能做出像样的作品。比赛截止前夕，恰逢前往北京参加国科大的活动，如井底之蛙跃出井口，方知世界之大，又重燃起斗志。可惜所剩时间不多，准备下一年认真备赛。

大三上，课业繁重，想备赛却有心无力。寒假，开始学习“一生一芯”，并通过预学习。大三下，正式备赛龙芯杯。

## 初赛备赛
### 大三下
大三下，课业压力小。三、四月复习Verilog知识，跟着《CPU设计实战》学习单周期和部分五级流水线CPU的设计。五月，参照学长A的思路制作了指令模拟器，与之不同的是，我将emu封装为类，方便调用，为此还学习了一段时间的 C++ 。六月，基本完成五级流水线的学习。六月底回家，休息一阵。

### 七月
七月一日，正式开始。先学习了 System Verilog，然后开始写代码。因为理论扎实，所以五级流水线代码写起来也比较快，一个星期就写好了，icache和bp也没有太大问题。在对拍阶段遇到一个问题，传统波形图看得眼花，于是自制了一个简易的波形图工具。后面串口有问题，花了一些时间去改。
![波形图工具](73383bb2-ed14-4f3a-8b68-885709605c47)


我的代码在ubuntu 24的虚拟机运行，而vivado装在ubuntu 18，每次综合都要复制粘贴代码，比较麻烦。因此将vivado装入ubuntu 24，提高效率。但兼容性有问题，便寻找解决办法。 <a href=https://xingwangzhe.fun/posts/1a282b79/ >Ubuntu 24.04 安装 Vivado 2018.3</a> 总结一下，因为一个底层库更新了，vivado无法识别。解决方法是将需要的库连接到最新的库。
```bash

sudo ln -sf /lib/x86_64-linux-gnu/libtinfo.so.6 /lib/x86_64-linux-gnu/libtinfo.so.5
sudo ln -sf /lib/x86_64-linux-gnu/libncurses.so.6 /lib/x86_64-linux-gnu/libncurses.so.5
sudo ln -sf /lib/x86_64-linux-gnu/libncursesw.so.6 /lib/x86_64-linux-gnu/libncursesw.so.5
```

把bitstream提交到平台时，还要一个一个点击，于是做了一个脚本，把bit流自动上传到各个测试题目。

七月中旬，突然通知今年wns要求为正，这样就不能无限制超频，利好复杂架构。五级流水线设计通过测试后，尝试单发乱序，把ex阶段和mem阶段并行，速度提升明显。因为用的是简单的乱序架构，所以一天时间就完成了，后续完成针对乱序的验证花了不少时间。

七月下旬，发现一个棘手的问题，我的设计会随机地无法通过测试，相同的bit流有时通过，有时不能。仿真无异常，说明是上板的问题。找不到错误，无奈之下把网页版的远程fpga封装成cli，让AI大范围跑测试找问题，最终定位到一组特定的指令序列 —— 连续st就会出错，增大延迟也不行。解决方法是在连续st之间插入强制we=0才解决。（特别注意，我把远程fpga封装成cli也是迫不得已，实在是bug太难找，请大家不要随意模仿）

七月中旬排行榜开启后，竞争激烈。七月下旬，我的成绩已远远落在后面，深感无力。尝试加入write buffer，勉强提升10ms，通过仿真发现 ld 和 st 相隔较近，buffer被频繁打断写入，提升不如预期。w buffer提升的10ms仍是杯水车薪，差距依然明显，各榜单都进不了前20。

### 八月
八月五日，初赛截止，身心俱疲，预感决赛无望，没再优化代码，在家躺了几天。八月十二日，决赛名单公布，发现自己进入决赛，十分惊喜。然而决赛人数较往年的50名增加至80名，并新增“优胜奖”，不再保底“三等奖”。也就是我大概率在50名开外，只能拿优胜奖，算是喜忧参半。

得知进决赛后，便开始新增指令，优化时序。检查时发现w buffer有问题，如果字节和字的访存交叉在一起，w buffer无法正确判断是否命中，访存会出错。为了稳定不出差错，并且时间也所剩不多不一定能改好，只能删掉w buffer。分支预测也有问题，二位饱和计数器只会向 11 移动，不会向 00 移动。但是分支预测不影响程序正确性，也几乎没有影响ipc，所以没再修改。优化时序是一件玄学的事情，修改一点sv代码，因为布线差异，时序就可能大不一样。抽卡抽到几个较好的时序，就没再修改。

19日提交最终代码，20号提交alpha测试。看群里有人的alpha测试有问题，庆幸我交的是比较稳定的版本，没有冒险把w buffer的版本交上去。

比赛题目相较于往年求和、比大小这类难一些.

``` 比赛题目

1. 题目： 二值点积运算
给定 0x40000 组 32 位输⼊ (lhs, rhs) ，计算每组输入的二值点积。

2. 计算规则：
每组输入由两个 32 位数据 lhs 和 rhs 组成，视为 32 位二值向量。每 bit 表示一个二值元素：bit 值 0 表示数学值 -1 ，bit 值 1 表示数学值 +1 。
定义：
A[j] = lhs[j] == 1 ? +1 : -1
B[j] = rhs[j] == 1 ? +1 : -1
其中 j = 0, 1, ..., 31 。每组的点积结果定义为：
result = A[0] * B[0] + A[1] * B[1] + ... + A[31] * B[31]
result 作为 32 位有符号整数存放。


3. 输入与输出：
输入位于 BaseRAM 0x1c200000–0x1c3fffff ，每组占 8 字节并按小端序交错存放：
lhs[i] = *(uint32_t *)(0x1c200000 + 8 * i)
rhs[i] = *(uint32_t *)(0x1c200004 + 8 * i)
result[i] = *(int32_t *)(0x1c400000 + 4 * i)
每组结果依次写⼊ ExtRAM 0x1c400000–0x1c4fffff。 
```


``` C

#define MEM32(a) (*(volatile unsigned int *)(a))

int main(void)
{
    unsigned lhs_addr = 0x1c200000;
    unsigned rhs_addr = 0x1c200004;
    unsigned result_addr = 0x1c400000;
    for(unsigned int i=0;i<0x40000;i++){
        unsigned lhs_i = MEM32(lhs_addr + i*8);
        unsigned rhs_i = MEM32(rhs_addr + i*8);

        int result_i=0,a0=0;

        unsigned temp_i = lhs_i ^ rhs_i;

        for(unsigned j=1;j!=0;j = j<<1){
            unsigned ta = (temp_i) & j;
            a0 += (ta == 0);
        }
        MEM32(result_addr + i*4) = (a0+a0-32); 
    }
}

```

C语言写的没通过，检查几次后发现是有个循环变量写错了，修改后正确了。

第一次正确通过在9点多，后来修修改改，一转眼就到11点了半。没有优化的空间，便坐着发呆，最后半个小时的反倒比前几个小时更加漫长。这次比赛倒不像学长A说的每次提交要40分钟，是ci 10分钟，平台检验10分钟，还算比较快，应该是优化了平台性能。比赛结束，签到离场，心中一阵空虚。说不上开心或伤心，感觉一切终于结束，也不再想究竟能不能拿奖，仿佛一切跟自己没了关系。

到云天苑餐厅，凭午餐票领取午餐。饭后，我继续在校内闲逛，同学B离校。天气炎热，烈日当头，我也没停留过久，不久便返回酒店休息。下午，和学长A交流了一下比赛情况和AI使用情况，深感AI对于当前竞赛环境的冲击。

颁奖后，是抽奖环节和领导致辞。一晃已经到11点半，匆匆赶回酒店，在楼下吃了红烧牛肉面。牛肉面肉少面多，汤很咸，但整体味道很好。吃完，赶紧返回房间收拾行李，随后沿原路返程。这次时间紧，跟前台说晚一个小时到下午一点退房，结果还是迟了。


### 行程反思
1. 退房前要仔细检查物品是否带齐。龙芯杯的短袖跟床被的颜色一模一样，都是白色，没看清，落在那里了。后来联系前台我，当时已经在公交车上，没时间返回，只能邮寄回来。
2. 订酒店要仔细看到学校的真实距离。预定时看到直线距离3公里，似乎不太远，到地方一导航才发现路线距离5公里。
